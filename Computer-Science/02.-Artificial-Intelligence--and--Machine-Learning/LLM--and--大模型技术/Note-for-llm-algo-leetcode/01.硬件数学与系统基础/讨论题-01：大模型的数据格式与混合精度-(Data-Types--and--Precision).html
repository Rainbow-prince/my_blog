NOTE

粗暴地讲，大模型是一堆数字，几十上百亿的参数，每一个参数都是一个数字。

这些数字在 GPU 中游走，在计算单元中跑来跑去。我们得知道这些参数长什么样子，或者最起码知道它多大，才能更好地了解大模型。

知道一个小数有多大，长什么样，有什么用？

  • 你要算显存够不够装模型？你得先知道每个参数占几字节
  • 你要理解量化 Quantization 为什么可以把大模型变小，你得先知道大模型的参数长什么样子

Q1：每种格式占多大？

1 Byte = 8 bits

格式占用全称备注
FP324 BytesFloating Point 32-bit 单精度浮点数最胖、最占地方、最精确
FP162 BytesFloating Point 16-bit 半精度浮点数砍掉一半、剩下一半
BF162 BytesBrain Float 16 脑浮点Google Brain 发明，和FP16一样大，但是设计不同（结构长得不一样）
INT81 ByteInteger 8-bit 8位整数不是小数了，是整数，更省空间
INT40.5 ByteInteger 4-bit 4位整数极致压缩，AWQ/GPTQ 量化用

估算公式：参数量 × 每个参数占多少字节 = 显存

Example: 7B 模型用 FP16 加载，那么它的体积是多大？

70亿 × 2 Bytes ≈ 14 GB

Q2：FP16 和 BF16 都是 16-bit，那它哪里不一样？

引入一个概念：浮点数是怎么用 bit 来表示一个小数的？任何一个浮点数，都由三部分拼成：

浮点数 = 符号位 Sign + 指数位 Exponent + 尾数位 Mantissa/Fraction

通俗一点，你可以把浮点数的表达，想象成科学计数法，比如一个数字 -1.234321 × 10^5

  • 符号位：正还是负（-）
  • 指数位：量级有多大（10^5，指数是5）
  • 尾数位：具体是多少（1.234321，也就是精度，如果精度差，可能就变成1.23）

Note

核心法则：

  • 指数位 → 决定范围（能表示多大的数）
  • 尾数位 → 决定精度（小数点后有多准）
符号位指数位尾数位最大值
FP3218233.4 × 10^38
FP16151065,504
BF161873.4 × 10^38

看出来了吗？FP16 和 BF16 总共都是 16 个 bit，但分配方式完全不同：

  • FP16：给尾数分了 10 位，给指数只分了 5 位 → 量得准但量不大（像一把精密的小尺子，最大才 65504）
  • BF16（Brain Float 16 脑浮点）：给指数分了 8 位，给尾数只留了 7 位 → 量不太准，但可以量很大的东西（像一把粗糙的大卷尺，最大到 10^38）

BF16 的设计，说白了就是把 FP32 直接砍掉后面 16 位尾数，指数位原封不动保留。粗暴但有效。所以 BF16 能表示的最大数值范围和 FP32 一模一样，只是小数没那么精确了。

Q3：实战训练——为什么 LLaMA 这些现代大模型都抛弃 FP16，拥抱 BF16（脑子浮点数）？

回忆一下 Q2 的表格：FP16 指数位只有 5 位，最大值才 65504。BF16 指数位有 8 位（跟 FP32 一样），最大值 3.4 × 10^38。

指数位少 → 范围窄，这是 FP16 的根本问题。具体来说，FP16 有两个致命缺陷：

缺陷一：天花板太低 —— 溢出 Overflow

训练深层 Transformer 的时候，Attention 算出来的 logits、没归一化的梯度……这些数值非常容易超过 65504。一旦超过，数值直接变成 NaN（Not a Number），然后整个训练就崩了，几百张 GPU 全白跑。

缺陷二：地板太高 —— 下溢出 Underflow

反向传播算出来的梯度，有时会非常非常小，小到 FP16 的精度根本识别不出来，超出它的精度范围，就直接被抹零了。梯度被抹零 = 模型学不到东西

FP16 时代的补救措施：Loss Scaling

  • 英伟达的文章： 2.3.1. Loss Scaling To Preserve Small Gradient Magnitudes

FP16 的上溢出缺陷，没有好的补救办法，只能祈祷别超过 65504。而其 下溢出的问题，工程师搞了一个叫 Loss Scaling 损失缩放 的机制来凑合：既然梯度太小会被抹零，那就放大 Loss，让梯度也跟着变大，FP16 就能看见了。

动态缩放虽然自动，但 Loss Scaling 终究是个打补丁的方案——增加了训练复杂度，而且只解决下溢出，溢出问题它管不了。

BF16：两个缺陷一起解决（两个愿望一次实现）

BF16 的指数位有 8 位（跟 FP32 一样），意味着：

  • 天花板拉到了 1038 → 溢出不可能发生
  • 地板也跟着降低了 （能表示更加接近于0的小数）→ 下溢出几乎不可能发生
  • Loss Scaling 整个机制直接不需要了，这就是”免调参”的意思：不是不用调参数了，而是整个补丁方案都不需要了

代价呢？BF16 尾数位比 FP16 少了 3 位（7 vs 10），精度差了一点。但神经网络本身就是个”粗线条”的统计模型，对微小精度损失很鲁棒 Robust，但对数值溢出非常脆弱。

"粗线条"是什么意思？

就是说神经网络不需要特别精确的数字，它就能工作。你把参数从 0.123456789 变成 0.123，少了好几位小数，模型照样能正常预测——它对精度损失很不敏感，这就是”鲁棒 Robust”的意思：不怕你精度粗糙。

为什么对溢出很脆弱？

因为一旦某个数超过了上限变成 NaN（不是一个数），这个 NaN 会传染。NaN 加任何数还是 NaN，NaN 乘任何数还是 NaN——就像病毒一样，一个数炸了，整层都炸了，整个模型就废了。

一句话：用一点精度换绝对稳定性，太值了。BF16 = 无脑稳定免调参。

Q4：混合精度训练 (AMP, Automatic Mixed Precision) 为什么要保留 FP32 主权重 (Master Weights)？

混合精度训练的意思是：前向传播 Forward 和反向传播 Backward 都用 16-bit 跑，这样省一半显存，还能加速。听起来很美好对吧？

但问题出在参数更新 (Optimizer Step) 这一步：

Wnew​=Wold​−LR×Gradient

Danger

训练到了后期，学习率 LR (Learning Rate) 通常很小（比如 10−5），梯度 Gradient 也很小，两者的乘积 ΔW 就是一个极其微小的更新量。

如果 Wold​ 也是用 16-bit 存的，还记得 Q2 说的吗？16-bit 的尾数位 Mantissa 很短，精度不够。这个极小的 ΔW 加上去之后，16-bit 根本认不出来——就像你往一杯水里加了一滴水，水位看着没变。这就是下溢出 Underflow，更新量被直接抹零了。

更新量被抹零意味着什么？模型彻底停止学习。

所以解决方案就是：优化器 Optimizer 里必须偷偷留一份 FP32 的主权重 Master Weights。它是权威版本、原始副本。每次的流程是：

  1. 从 FP32 主权重 截断出一份 16-bit 副本，送去前向/反向计算（打工的）
  2. 算出梯度后，回到 FP32 主权重 上做更新（精度高，一滴水也认得出来）
  3. 更新完后，再从 FP32 截断出新的 16-bit 副本，继续下一轮

这就是为什么开启全参训练后，显存占用远大于静态权重——因为你同时存了 16-bit 的权重和 32-bit 的主权重。

Q5：A100（Ampere 架构） 有什么了不起的？

A100（Ampere 架构）能成为统治大模型时代的标杆，核心原因之一就是硬件层面做了两件大事：

第一件：原生支持 BF16 Tensor Core

  • A100 之前的 V100（Volta 架构），Tensor Core 只支持 FP16。所以早期训练大模型的人饱受溢出之苦。
  • A100 的第三代 Tensor Core 直接加了 BF16 原生支持，算力翻倍的同时再也不用担心溢出了。

第二件：发明了 TF32 (TensorFloat-32)

NVIDIA 想让开发者不改动任何代码就白嫖加速，”杂交”出来了 TF32 格式。把 FP32 和 FP16 的优点各取了一半：

符号位指数位尾数位来自谁存储方式
FP321<font color=”#ffc000”>823—32 bit
FP161 510—16 bit
TF3218（从 FP32 拿的）10（从 FP16 拿的）拼出来的19 bit，但按 32 bit 存
  • 指数位用了 FP32 的 8 位 → 范围跟 FP32 一样大，不会溢出
  • 尾数位用了 FP16 的 10 位 → 精度够用，比 BF16 的 7 位还高
  • 当你在 PyTorch 里用 FP32 做矩阵乘法时，A100 会在内部偷偷把数字截断成 TF32 飞快算完，再转回 FP32 输出
  • 你什么代码都不用改，速度就直接快了好几倍

Q6：H100 的 FP8 是什么黑科技？

到了 H100 这一代，模型越来越大（7B → 70B → 万亿参数），16-bit 的计算速度已经跟不上了。换成 8-bit 的话，每个数字小了一半，GPU 同样时间里能处理的数据量直接翻倍——搬运快了，计算也快了。NVIDIA 就直接搞了 8-bit 的 FP8。

但 8 个 bit 就这么点空间，又要范围又要精度，根本不够分啊。所以 NVIDIA 非常聪明地把 FP8 拆成了两种独立的变体，用于深度学习的不同生命周期：

格式一句话指数尾数用在哪
E4M3牺牲范围保精度43前向传播、激活值
E5M2牺牲精度保范围52反向传播、梯度

为什么前向和反向要分开？因为前向计算产生的数值分布比较集中，不需要太大范围，但对精度更敏感；而反向传播的梯度数值跨度极大，非常容易下溢出，所以必须多给指数位保命。

这种把 8 个 bit 的潜力压榨到极致的设计，让 H100 的 FP8 算力比 A100 的 FP16 又翻了一倍。
