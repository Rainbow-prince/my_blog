1. 总览：知识图谱提取 Prompt 的通用模式 {#1-总览}

所有主流框架的 KG 提取 Prompt 都遵循一个共同的模式：

flowchart LR
    A["📝 原始文本"] --> B["🤖 LLM + Prompt"]
    B --> C["🔗 实体 + 关系"]
    C --> D["📊 知识图谱"]
    
    subgraph Prompt 组成
        P1["角色/目标定义"]
        P2["步骤指导"]
        P3["输出格式规范"]
        P4["Few-shot 示例"]
        P5["约束与规则"]
    end

IMPORTANT

核心设计原则：好的 KG 提取 Prompt 必须同时解决 “提取什么”（实体类型、关系类型）和 “怎么输出”（结构化格式）两个问题。

2. LlamaIndex 的 Prompt 设计 {#2-llamaindex}

LlamaIndex 提供了 3 种递进式的 KG 提取 Prompt，从简单到复杂，覆盖不同场景。

源码位置: default_prompts.py

2.1 DEFAULT_KG_TRIPLET_EXTRACT_TMPL — 基础三元组提取

最简洁的提取 Prompt，适合快速原型验证：

设计特点：

维度说明
输出格式(subject, predicate, object) 纯文本元组
Schema 约束❌ 无，完全开放式
Few-shot✅ 2 个简单示例
数量控制{max_knowledge_triplets} 参数
适用场景探索性分析，快速验证

2.2 DEFAULT_DYNAMIC_EXTRACT_TMPL — 动态类型提取

引入了 初始本体 (Initial Ontology) 概念，允许 LLM 在此基础上自由扩展：

设计特点：

维度说明
输出格式JSON 数组，含类型信息
Schema 约束⚡ 半约束：提供初始类型，允许扩展
Few-shot✅ 1 个含多种实体类型的复杂示例
实体规范使用完整形式、限制 3-5 词
适用场景领域自适应，逐步构建本体

TIP

关键设计亮点：“Use these types as a starting point, but introduce new types if necessary” — 在约束和灵活性之间取得平衡。

2.3 DEFAULT_DYNAMIC_EXTRACT_PROPS_TMPL — 带属性的动态提取

在 2.2 基础上增加了 实体属性和关系属性 的提取：

新增要素：head_props / relation_props / tail_props 字典，用于捕获更精细的属性信息（如日期、数值、状态等）。

2.4 LlamaIndex 的 Extractor 抽象

LlamaIndex 通过 3 种 Extractor 组件对应上述 Prompt：

graph TD
    A["PropertyGraphIndex"] --> B["SimpleLLMPathExtractor"]
    A --> C["DynamicLLMPathExtractor"]
    A --> D["SchemaLLMPathExtractor"]
    
    B -->|"使用"| P1["基础三元组 Prompt"]
    C -->|"使用"| P2["动态类型 Prompt"]
    D -->|"使用"| P3["严格 Schema Prompt"]
    
    style A fill:#4a9eff,color:#fff
    style B fill:#ff6b6b,color:#fff
    style C fill:#ffa94d,color:#fff
    style D fill:#51cf66,color:#fff
  • SimpleLLMPathExtractor：无 Schema，开放提取
  • DynamicLLMPathExtractor：提供初始 Schema，允许扩展
  • SchemaLLMPathExtractor：严格遵循预定义 Schema

3. Microsoft GraphRAG 的 Prompt 设计 {#3-graphrag}

GraphRAG 的 Prompt 设计是目前业界最复杂、最精炼的知识图谱提取方案。

源码位置:

  • prompts/index/extract_graph.py （运行时默认 Prompt）
  • prompt_tune/template/extract_graph.py （Prompt 微调模板）

3.1 核心提取 Prompt — GRAPH_EXTRACTION_PROMPT

3.2 GraphRAG 独创的 Gleanings 机制

IMPORTANT

Gleanings（拾遗） 是 GraphRAG 最具创新性的设计——通过多轮迭代确保实体不遗漏。

GraphRAG 定义了两个后续 Prompt：

CONTINUE_PROMPT — 迭代提取遗漏实体：

LOOP_PROMPT — 判断是否需要继续：

flowchart TD
    A["文本块输入"] --> B["首轮提取"]
    B --> C{"检查完整性"}
    C -->|"可能遗漏"| D["CONTINUE_PROMPT"]
    D --> E["补充提取"]
    E --> F["LOOP_PROMPT"]
    F -->|"Y: 有遗漏"| D
    F -->|"N: 完成"| G["合并所有提取结果"]
    C -->|"完整"| G
    
    style D fill:#ff6b6b,color:#fff
    style F fill:#ffa94d,color:#fff

TIP

Gleanings 解决了 LLM 在处理密集实体文本时的 “attention drift” 问题。配置中 max_gleanings 参数控制最大迭代轮次（默认 1）。

3.3 GraphRAG 的 4 种 Prompt 变体

变体实体类型约束输出格式用途
GRAPH_EXTRACTION_PROMPT✅ 指定类型列表Tuple (<|> 分隔)默认方案
GRAPH_EXTRACTION_JSON_PROMPT✅ 指定类型列表JSONJSON 友好场景
UNTYPED_GRAPH_EXTRACTION_PROMPT❌ 不指定，LLM 自建Tuple开放探索
(Example templates)——Few-shot 生成

3.4 GraphRAG 的 Prompt Auto-Tuning

GraphRAG 提供了 prompt_tune 模块，可根据用户的实际语料自动生成定制化 Prompt：

  1. 从语料中采样文本片段
  2. 让 LLM 分析领域特征，生成 domain persona
  3. 基于模板自动生成包含领域特定 few-shot 示例的提取 Prompt
  4. 自动扩展实体类型（例如从默认的 PERSON/ORGANIZATION/GEO 扩展到包含 MUSIC_GENRE/LOCATION 等）

4. LangChain LLMGraphTransformer 的 Prompt 设计 {#4-langchain}

LangChain 的方案更偏向工具化设计，核心思路是：

4.1 双模式设计

graph LR
    A["LLMGraphTransformer"] --> B{"LLM 支持 Function Calling?"}
    B -->|"是"| C["Tool-based 模式"]
    B -->|"否"| D["Prompt-based 模式"]
    
    C -->|"Pydantic Schema 定义输出"| E["结构化输出"]
    D -->|"Prompt 中显式定义格式"| E

4.2 System Prompt

差异化特点：

  • 优先使用 Function Calling / Tool Use（减少格式解析错误）
  • 通过 Pydantic 模型定义输出 Schema
  • 支持自定义 Prompt 与默认 Prompt 融合

5. 社区最佳实践与经验 {#5-社区经验}

基于 Reddit、知乎、CSDN 等技术社区的讨论，以下是关键经验总结：

5.1 Prompt 设计技巧

技巧说明来源
严格输出格式使用 JSON / 结构化元组，加入 “if unsure, output null”Reddit
分步推理Step 1: 识别实体 → Step 2: 识别关系（CoT 风格）Reddit/CSDN
实体规范化使用完整名称，避免缩写（‘USA’ → ‘United States of America’）LlamaIndex 源码

领域自适应为不同领域定制实体类型和示例GraphRAG auto-tune

5.2 常见陷阱

WARNING

递归悖论：用 LLM 来提取知识图谱，再用知识图谱来增强 LLM 的检索——本质上是在”不确定性上叠加不确定性”。因此提取质量验证至关重要。

  • Attention Drift：密集实体文本中 LLM 容易”遗忘”后半段实体 → GraphRAG 的 Gleanings 机制正是为此而生
  • 关系噪声：Zero-shot 提取会产生大量噪声关系 → 需要 Schema 约束或后处理过滤
  • 实体消歧：同一实体的不同称呼（如”Apple”既可以是公司也可以是水果）→ 提供上下文窗口、使用完整名称
  • Prompt 过长：更长的 Prompt ≠ 更好的结果。“Better structure > bigger prompts”

5.3 进阶策略

  1. 构建统一知识图谱：避免构建多个碎片化的图谱，保留跨领域洞察力
  2. 本体 (Ontology) 驱动：预定义本体可以帮助消歧和推理
  3. Prompt + 微调结合：在关键场景下对小模型做微调，比单纯依赖 Prompt 更稳定
  4. 时间信息保留：在 Prompt 中强调提取日期/时间信息，为时间线推理提供基础
